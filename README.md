# 無限煉製 · 煉製軌跡 v1.3.1

一個幫助你紀錄網頁遊戲《無限煉製》的合成路徑、以及匯入他人合成路徑的助手。

給《[無限煉製 Infinite Alchemy](https://pillars-of-creation.funtuan.work/)》用的 Chrome 擴充套件（Manifest V3）。

> 版本號寫在擴充套件名稱、儀表板標題與標題列徽章上（都從 manifest 讀，不會各說各話）。
> **改版後那裡沒變，就表示還沒按「重新載入」。**
>
> ⚠️ **資料夾名稱刻意不帶版本號。** 未封裝擴充套件的 ID 是由資料夾路徑算出來的——
> 路徑一改，Chrome 就當成另一個擴充套件，得移除重裝，而且**既有資料不會跟過來**。
> 升版只改 `manifest.json`，資料夾維持原名，按「重新載入」就好。

核心是一份**跨帳號、可互相分享的共用配方表**：把你煉過的每一組材料——成功、崩解、祈禱——全部記下來，
然後在你花魔力之前先告訴你結果，並依照**你這個帳號手上有的東西**算出最短合成路徑。

資料只存在你自己的瀏覽器裡，不上傳任何地方。

## 安裝

1. 到 [Releases](../../releases) 下載 `infinite-alchemy-helper-vX.X.X.zip` 並解壓縮
2. 開啟 `chrome://extensions/`（Edge 是 `edge://extensions/`）
3. 右上角開啟「**開發人員模式**」
4. 點「**載入未封裝項目**」，選擇解壓縮後的資料夾
5. 重新整理遊戲頁面
6. 按浮層或儀表板右上角的「**⟳ 更新**」跑一次

需要 Chrome / Edge 111 以上版本。更新紀錄見 [CHANGELOG.md](CHANGELOG.md)。

> ### ⚠️ 資料夾路徑決定你的資料會不會不見
>
> 未封裝擴充套件的 ID 是由**資料夾路徑**算出來的。路徑一改，Chrome 就當成另一個擴充套件，
> **既有的配方表與軌跡不會跟過來**。
>
> - **升版時沿用同一個資料夾**：把新檔案覆蓋上去，再到 `chrome://extensions` 按「重新載入」
> - 用 GitHub 的「**Source code (zip)**」或 clone 的話，解壓資料夾會叫 `..._helper-1.3.1`，
>   **版本號在路徑裡**——下一版就換路徑了。請自己改成一個固定名稱（例如 `無限煉製擴充套件`）再載入
> - Releases 裡附的 `infinite-alchemy-helper-*.zip` 解壓後固定是 `無限煉製擴充套件`，沒有這個問題

## 兩層資料

| | 範圍 | 內容 |
| --- | --- | --- |
| **共用配方表** | **全域、跨帳號** | 哪些材料組得出什麼、哪些會崩解、哪些要祈禱才成。配方是世界的性質，不因帳號而異——只標記「是誰、用哪個帳號煉出來的」。**這是可以匯出分享的那一份。** |
| **待煉** | **全域、跨帳號** | 你之後打算煉的組合與整條路徑（見下）。「這個值得做」跟帳號無關，切帳號不該讓清單消失。 |
| **帳號狀態** | **分帳號** | 持有的造物（素材櫃）、金砂、魂元、魔力，以及你自己的煉製軌跡。 |

所以切換帳號煉金沒問題：配方會一直累積下去不會分裂，但「我現在能做什麼」永遠照當下這個帳號的素材櫃算。

帳號以 `/api/me` 的 **`id`** 分辨，不是名號——名號可以在工坊設定改（`PATCH /me`），改名不會讓紀錄斷成兩個人。

## 共用配方表：失敗也是知識

每一組材料都是**普通與祈禱分成兩軌**記錄的，成功與失敗都收：

| 判定 | 意思 | 你該做什麼 |
| --- | --- | --- |
| **已知可成** | 普通煉就會成功，並顯示會煉出什麼 | 產物不是你要的就別煉，省一次魔力 |
| **普通會崩解，祈禱可成** | 這組普通失敗過，但祈禱成功過 | 直接祈禱，不要先浪費一次普通合成 |
| **祈禱煉得出來** | 只有祈禱的成功紀錄，普通沒人試過 | 想省魂元可以先試普通 |
| **已知會崩解** | 普通失敗過，祈禱還沒人試 | 想賭的話直接用祈禱試 |
| **普通與祈禱都失敗過** | 兩邊都試過都不行 | 別碰 |
| **尚無紀錄** | 沒人試過 | 煉出來就是你的首發 |

**後來的成功會覆蓋先前的失敗。** 一組材料只要成功過一次（無論普通或祈禱），那一軌就永遠記成成功——
配方一旦被發現就存在了，先前的崩解只代表當時還沒人找到；反過來，之後偶發的失敗不會把已知的成功降級。

## 配方怎麼進到表裡

三個來源，都會標記出來：

1. **你自己煉的**（`自己煉的`）— 安裝之後你在遊戲裡按下的每一爐，即時記錄，含崩解原因與魔力消耗
2. **更新抓回來的**（`遊戲回填`）— 按「⟳ 更新」時從遊戲讀回你的合成紀錄與你發現的配方，
   以及**全服動態收集**（見下）抓到的其他玩家配方
3. **別人分享的**（`他人分享`）— 匯入別人匯出的檔案

另外，你在遊戲裡**自己點開**某個造物看配方時，擴充套件會旁聽那個你本來就發出的回應，順手收進表裡——
逛遊戲本身就在長配方，不會多發任何一個請求。

## 全服動態收集（預設關閉）

**遊戲內浮層**與儀表板「資料」頁各有一顆開關，撥的是同一個設定（`chrome.storage.local`），
兩邊會即時同步。開啟後只要遊戲分頁開著，就會**每 30 秒**讀一次 `/api/ranking/recent`
（遊戲自己的「全服最新的合成紀錄」），把所有玩家的配方收進共用配方表。配方表長得快很多，
查配方與規劃也就更準。

- **只進共用配方表，不會進你的軌跡**——那些是別人煉的，不是你做過的事
- 發現者照遊戲回報的名字記，**不會掛上你的帳號**
- 沒有產物的那幾筆（崩解）一樣收，那是最省魔力的知識
- 開好幾個遊戲分頁**也只有一個會輪詢**（背景服務發租約），不會變成好幾倍請求
- 同一筆紀錄看過就不再送給背景
- **預設關閉**，因為它會持續發請求。覺得吃緊隨時關掉，開關即時生效

「資料」頁會顯示已讀取幾次、看過幾筆、實際併入幾組配方，方便你判斷值不值得開著。

## 「⟳ 更新」按鈕

更新做兩件事：**抓回你目前持有什麼**（規劃器要靠它算路徑），以及**把你會的配方收進共用配方表**。
用**遊戲分頁自己的登入身分**讀這六支，全部都是「我自己的」：

1. `/api/me` — 帳號、金砂、魂元、魔力、素材櫃格數
2. `/api/me/discoveries` — 素材櫃完整內容（我持有的造物）
3. `/api/me/seeds` — 原初五元素
4. `/api/me/inventions` — **世上創生**（用來判定哪些算全服首煉，見下）
5. `/api/combine-log` — 我自己的煉製紀錄，**含崩解與祈禱** → 軌跡 ＋ 共用配方表
6. `/api/me/recipes?offset=N` — 所有由我首度發現的配方，分頁一次拿一批 → 軌跡 ＋ 共用配方表

**不會對每個造物逐一發問**，幾個請求就好。需要開著遊戲分頁（背景服務的 fetch 帶不到遊戲的登入 cookie）。

補回來的紀錄在軌跡裡標成「**遊戲紀錄**」，可以單獨篩選。去重保守：同一帳號只要已經有「相同組合＋相同結果」的紀錄就不再補。

### 順手看一眼有沒有新版本

更新跑完時，會順便問一次 GitHub 的 `releases/latest`。**比你現在裝的新**才會在浮層與儀表板浮出一顆
「**⬆ 有新版本 vX.Y.Z**」，按下去開發布頁，要不要更新你自己決定——不會自動下載、也不會自動安裝。

- **只在按「更新」時查**，而且**一小時內只查一次**（GitHub 未登入的 API 一小時 60 次）
- 開儀表板或遊戲分頁只讀上次查到的結果，不會自己去打 GitHub
- 查不到（斷網、GitHub 掛了、被限流）就當作沒這回事，不會害更新看起來失敗
- 草稿與預發布不算數

> 擴充套件**沒辦法自己覆蓋自己**——Chrome 不允許擴充套件改寫自己的檔案，
> `chrome.runtime.requestUpdateCheck()` 也只對商店安裝的擴充套件有效。
> 所以更新一律是：下載 zip → 解壓覆蓋**同一個資料夾** → `chrome://extensions` 按「重新載入」 → 遊戲分頁 F5。

### 「全服首煉」與「首度發現配方」是兩回事

遊戲自己的排行榜就把這兩件事分開（`inventor` vs `recipe`）：

| 標記 | 遊戲裡叫什麼 | 意思 | 資料來源 |
| --- | --- | --- | --- |
| **全服首煉** | 造物主／世上創生 | 全世界第一個煉出**這個造物**的人是你 | 即時：`/api/combine` 的 `isGlobalFirst`；補回來的：比對 `/api/me/inventions` |
| **首度發現配方** | 新配方 | 第一個找到**這條做法**的人是你（同一造物可以有很多條做法） | 即時：`isNewDiscovery`；補回來的：`/api/me/recipes` 回的每一筆 |

所以「新配方」的數字通常遠大於「世上創生」——你可能為別人早就創生過的造物找到一條新做法。
補回來的紀錄只有在產物出現在你的**世上創生名單**裡時才會掛上全服首煉。

### 軌跡到底有多完整？

| 資料 | 拿得完嗎 |
| --- | --- |
| **我首度發現的配方** | ✅ 完整。`/me/recipes` 有 `offset` 分頁，一路翻到 `hasMore` 為 false |
| **我的煉製紀錄（含崩解）** | ⚠️ **只有最近約 100 筆**——這是遊戲伺服器的上限，不是擴充套件的。`/combine-log` 沒有分頁參數，擴充套件會試 `limit` 與 `offset` 兩種寫法，伺服器都不理會就停手（見下） |
| **別人先發現、但我也煉過的組合** | ❌ 除非落在 `/combine-log` 回傳的範圍內，否則拿不到 |
| **當時花了多少魔力、崩解原因原文** | ❌ 遊戲不回溯這些，補回來的那幾筆會是空的 |

所以「從開帳號到現在的完整紀錄」目前**做不到**——但你首度發現的配方是完整的，煉製紀錄拿得到最近那批，
之後即時記錄的部分則是百分之百完整（含崩解原因與魔力）。

#### 為什麼煉製紀錄卡在 100 筆

`/api/combine-log` 一次只回**最近 100 筆**，而且沒有分頁參數。擴充套件每次更新都會探測兩種常見寫法：

1. `?limit=1000` — 要得比預設多就採用
2. `?offset=100` — 有回新資料就一頁一頁翻到底

兩個都被忽略（伺服器回一模一樣的內容）就立刻停手，**整趟最多只多打兩個請求**。
更新完成訊息會直接寫「遊戲只給最近 100 筆」，讓你知道那是遊戲的上限而不是擴充套件漏抓；
哪天遊戲支援了分頁，同一段程式會自動翻更多，不用改。

## 遊戲內浮層

遊戲畫面右下角有個小浮窗（點標題列可收合）。刻意只做一件事——**在你按下去之前告訴你結果**：

- **你在遊戲裡把材料放進煉製台，兩個框就自動填上**，判定立刻出來：已知可成（顯示會煉出什麼、誰先發現的）／已知會崩解／普通崩解但祈禱可成／尚無紀錄
- 只放一樣材料時，遊戲那顆按鈕會變成「萃取」，判定也會標成 **`萃取：`**，不會跟煉成的結果搞混
- **想查還沒放進去的組合**，直接在框裡打字就好。自動填的框線比較亮，一眼分得出來
- **⟳ 更新按鈕**與進度顯示、**▤** 開儀表板、**－** 收合
- 有新版本時會浮出一顆「**⬆ 有新版本 vX.Y.Z**」，按下去開 GitHub 的發布頁（見上）
- **全服動態收集開關**（見上，預設關閉）——跟「資料」頁那顆是同一個設定，撥哪邊都一樣
- **待煉清單**（預設收合）——放你之後要煉的組合與整條路徑，見下

自動偵測讀的是煉製台的格子：

```html
<div class="workbench"><div class="slots">
  <div class="slot filled"><div class="chip r3"><span>🧟</span><span>殭屍</span></div></div>
  <span class="op">＋</span>
  <div class="slot">…</div>          <!-- 沒放東西的格子沒有 filled -->
</div></div>
```

萬一遊戲改版換掉這塊，浮層會退而求其次去讀材料列表裡被點亮的 `.chip.selected`；再抓不到就純手動輸入，
記錄功能完全不受影響。**偵測不到煉製台的時候不會去動你打的字**——切到別的分頁看東西，框裡的查詢會留著。

「現在手上就能煉」清單在儀表板的**怎麼煉**頁，浮層不放——那是慢慢看的東西，不該擋在遊戲畫面上。

### 待煉：魔力不夠時先存起來，之後照著做

判定列下面有一條**預設收合**的「待煉」，點開就是整份清單。裡面放兩種東西：

**① 單一組合** — 在遊戲裡選好兩樣材料，判定那一行的**最右邊有一顆星星**，預設是暗的。
點亮 ★ 就記下來，魔力夠了再回頭試。

- **只存材料，不存結果**——每次展開都用當下的共用配方表重算。所以匯入別人的配方之後，
  原本寫「尚無紀錄」的那幾筆會自己變成有答案，這正是「值得回頭看一眼」的訊號
- 已知的直接寫出判定與產物（`✅ 已知可成 → 🌋 地熱`），沒人試過的就寫 `❓ 尚無紀錄`
- 試過之後**不會**自動移除——結果會顯示在那一列，看完再自己 ✕ 掉。
  （崩解之後你可能還想改用祈禱再試一次，自動刪掉反而礙事）

**② 整條路徑** — 在儀表板「怎麼煉」查出路徑後按「**📌 存進待煉**」，整條就進來了。
展開之後是編好號的步驟，可以**邊對照邊往煉製台放材料**。

- **煉完一步，那一行自動消失**，剩幾步一目瞭然
- **整條煉完，它自己就不見了**——不用回頭清
- 擴充套件沒看到那一爐（例如在別的瀏覽器煉的）就按那一行的 **✓** 手動劃掉，免得整條卡著
- 同一個目標只留一條，重新規劃就覆蓋——不然同一個東西會存出好幾條互相矛盾的路
- 排不出順序的路徑不給存（現在很少見了，見下面「會繞回目標的配方」）

兩種都**跨帳號共用**，切帳號清單不會消失；收合狀態會記住，標題顯示目前有幾筆；
每筆右邊的 **✕** 可以整筆移除。

### 「怎麼煉」＝ 步驟表 ＋ 路徑樹

兩者畫的是**同一條路**：規劃器先用你手上的東西算出路徑，樹只是把它攤開成圖。
樹會停在你**已持有**的節點（不必再往下煉），這也是它跟單純的「族譜」不一樣的地方。

同一個造物常常有好幾種做法，點節點上的「**另有 N 條配方 ⇄**」可以換一條看，**步驟表會跟著重算**。

算出來的路徑可以按「**📌 存進待煉**」丟到遊戲內浮層，煉的時候邊對照邊做（見上）。

### 會繞回目標的配方一律當作不存在

配方表裡真的會出現繞回去的東西。假設要煉 **X**：

```
A ＋ B ＝ C
C ＋ B ＝ D
A ＋ X ＝ F      ← 這條要先有 X 才做得出 F
D ＋ F ＝ X
```

要有 F 得先有 X，要有 X 得先有 F——推薦的路徑**絕對不該長這樣**。
所以規則是：**把最後接成環的那一步拔掉**。當作 `A＋X＝F` 不存在，F 就變成一個
**葉節點**——跟 A、B 同性質，你自己想辦法弄到（市集買得到就買）。路徑照樣給得出來：

```
1. A ＋ B → C
2. C ＋ B → D
3. D ＋ F → X          F 標成缺料
```

- F 如果**還有別條**不會繞回去的做法，就換用那條，不會被拔掉
- 一次只拔一個、拔完再算，才不會把「其實只是排在後面」的造物也一起打成缺料
- 拔的時候會避開你正在查的那個目標——拔掉它就沒答案可看了
- 樹上不會再出現繞回去的節點

萬一你自己在樹上換配方換出了環，畫面會直說「**這條路走不通**」、指出是哪個造物，
並把配方改成不編號（`・`）——那不是可以照著做的順序。按「↺ 回到自動選的路徑」即可。

### 兩種模式

- **最短路徑**：合成次數最少，必要時允許用到你沒有的材料（會列出來要你去買）
- **最少未知**：盡量只用手上有的東西，寧可多煉幾步

### 演算法（以及它的極限）

從你持有的東西往外擴散，每次結算成本最低、且材料都已就緒的配方——形式上是**有向超圖上的最短
hyperpath**（一條配方＝兩個材料指向一個產物）。成本是 `(缺料數, 步數)` 兩個數字，兩種模式只差在誰優先；
步數算的是**路徑上用到的造物種類數**，共用的中間產物只算一次（合成不消耗材料，煉過就一直有）。

**這是啟發式，不保證是最短的那條。** 正是「共用只算一次」這件事讓 Dijkstra 的最佳性保證失效——
這個問題等價於 directed Steiner tree，是 NP-hard 的（即使每條配方只有一個產物也一樣）。
真要追最佳解，多項式時間內連 poly-log 近似都還是開放問題，不是瀏覽器裡該做的事。

實際上做了兩件事讓它又快又夠好：

- **算完就存著**：一份配方表＋一個素材櫃只算一次，之後查幾十個目標都是直接讀。
  五萬條配方第一次 0.37 秒，之後每次 **0.5 毫秒**
- **算完再修一次**：逐一問「這個造物改用另一條配方，總步數會不會變少？」——貪婪最常漏掉的就是
  「另一條配方用的材料我本來就要煉」。只接受嚴格更好的換法，所以**不可能比原本差**，
  實測平均少 5% 步數

## 配方共享

這是這個擴充套件的重點功能。

**匯出**（資料頁 →「📤 匯出配方（分享用）」）
只出共用配方表，**不含**你的軌跡、素材櫃與帳號 id，發現者只留名字。檔案小，可以直接傳給別人。

**匯入**（資料頁 → 匯入）
把別人給的檔案吃進來，**只併共用配方表**，不會動到你自己的軌跡。

合併是以「材料組合」為主鍵（材料順序不影響），所以同一組配方**不會變成兩筆**，而是併進同一筆：

| 欄位 | 合併規則 |
| --- | --- |
| **判定** | 對方成功 → 那一軌就是成功（你原本崩解的會被救回來）；對方失敗只在你還沒成功過時才標成失敗 |
| **嘗試次數** | 累加，所以畫面上寫「**一共**嘗試過 N 次」——你的加上所有匯入來源的 |
| **產物／emoji／類型** | 你已經有的不覆蓋（自己煉到的最準），你沒有的才補上 |
| **發現者** | 時間**較早**的那位保留 |
| **來源** | 加上「他人分享」，可以在共用配方表頁篩選 |

> 同一份檔案匯入兩次，次數會算兩次（判定不受影響，只是那個數字會偏大）。

**吃進來之後**：查配方查得到你沒試過的組合、規劃器能用別人的配方替你算路徑、浮層在你選材料的當下就顯示別人試過的結果、
儀表板「怎麼煉」頁的「現在手上就能煉」清單會冒出更多你原本不知道能做的東西。

大家互相匯入，配方表就會越來越完整。

## 清空與重置

「資料」頁最底下有兩顆，都無法復原，建議先按「匯出 JSON」備份：

- **只清軌跡** — 刪掉煉製軌跡，保留共用配方表、素材櫃與帳號狀態
- **完全重置** — 全部清掉（含待煉），回到**剛安裝的狀態**。想重跑一次「全新帳號按更新會怎樣」就用這個

## 疑難排解

**更新跑完了，但某些東西是空的**

按「資料」頁的「**診斷**」。它會把每支端點的原始回應攤開來——HTTP 狀態、頂層欄位名、每個陣列的筆數、第一筆長什麼樣。
情況通常是這兩種之一，報告上會直接標出來：

- `HTTP 401 / 403` — 那支端點需要登入或沒有權限
- `⚠ 找不到預期的欄位「xxx」` — 遊戲改了欄位名，把報告貼出來就能對著修

更新過程中若有端點失敗，完成訊息下方也會直接列出是哪幾支、錯在哪裡。

**按「更新」出現「背景服務沒有回應」**

擴充套件改版後，Chrome 不會自動重啟舊的 service worker。依序做：

1. `chrome://extensions` → 找到本擴充套件 → 按「**重新載入**」
2. 重新整理**遊戲分頁**（F5）
3. 重新整理**儀表板頁面**

同一個地方點「**服務工作處理程序 / service worker**」可以看背景的 console，有紅字請把它貼出來。

**「請重新整理遊戲分頁」** — 擴充套件更新後，已開著的遊戲分頁跑的還是舊的 content script，F5 一下就好。

**「已經有一個更新在跑了」** — 按進度列旁邊的「取消」。分頁被關掉造成的卡住，90 秒沒進度會自動解除。

## 運作方式

```
遊戲頁面 (MAIN world)                       擴充套件
  src/inject.js  ── 包住 window.fetch
       │  旁聽 combine / refine / me / discoveries / nodes/*/recipes /
       │        combine-log 的 clone()，不改寫任何回應
       │  postMessage
  src/content.js (ISOLATED world)
       │  ├─ 橋接事件給 service worker
       │  ├─ 執行「更新」與「診斷」（唯一帶得到登入 cookie 的地方）
       │  └─ 掛上 src/overlay.js 浮層（Shadow DOM，不污染遊戲樣式）
       │  chrome.runtime.sendMessage
  src/background.js ──► IndexedDB
       │                 attempts / knowledge / inventory / accountState / goals / meta
       ▼
  ui/dashboard.js · ui/popup.js
  src/knowledge.js（配方表）· src/planner.js（規劃）· src/analysis.js（路徑樹）
```

擴充套件主動對遊戲發請求只有三種情況：你按下「**更新**」、你按下「**診斷**」、
以及你自己開啟「**全服動態收集**」（預設關閉）。其餘時間都只是旁聽你本來就會發出的請求。

對遊戲以外唯一會連出去的地方是 **GitHub 的 `releases/latest`**，只在按「更新」時查、一小時一次，
只讀公開的版本號，不送出任何東西。`host_permissions` 就這兩個網域。

## 已知限制

- **安裝前的煉製歷史補得回多少，取決於 `/api/combine-log` 給多少**（見上面「軌跡到底有多完整？」）。你首度發現的配方是完整的。
- **規劃器只知道配方表裡有的東西。** 表越完整越準——多按幾次更新、或跟別人互相匯入。
- 持有物是快照＋增量：更新時抓完整素材櫃，之後煉出、清出會即時跟著改；市集買入等其他管道要等下次更新才會反映。
- 魔力消耗是用餘額前後相減**推估**的；中途補魔力或月卡自動回復時，該筆可能顯示不出來。
- 帳號靠 `/api/me` 認定。正常切帳號沒問題；但若在 `/api/me` 回來之前就搶著煉第一爐，那一筆可能還掛在上一個帳號名下。
- 浮層的自動偵測依賴遊戲的 `.chip.selected` class，遊戲改版可能失效——失效時自動降級為手動輸入。
- 遊戲若改動 API 路徑或欄位名稱，用「診斷」可以立刻看出是哪一支、哪個欄位變了。
